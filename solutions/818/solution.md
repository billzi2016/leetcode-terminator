## 解法一：暴力 / 最直觉解

**思路**  
最直观的想法是把所有可能的指令序列都枚举一遍，直到找到能把小车恰好停在 `target` 位置的最短序列。  
这里可以把每一次指令执行后的**状态**看成一个节点，状态由两个数字决定：

- `position`：当前所在的坐标  
- `speed`：当前的速度（正数表示向右，负数表示向左）

从初始状态 `(0, +1)` 出发，每一步我们都有两种选择：

1. **加速（A）**：`position += speed`，`speed *= 2`
2. **掉头（R）**：如果 `speed > 0`，则 `speed = -1`；否则 `speed = +1`（速度变成相反方向且大小为 1）

因为我们要求**最少指令数**，可以使用 **广度优先搜索（BFS）**：先把所有一步能到达的状态放进队列，随后一次遍历完所有一步能到达的状态后，再继续往后扩展。BFS 按层遍历的特性保证第一次碰到目标位置时使用的指令数就是最少的。

为了防止无限扩张（比如一直往左跑），我们用一个 `visited` 集合记录已经访问过的 `(position, speed)`，并且只把坐标在 `[-2*target, 2*target]` 区间内的状态加入队列——超过这个范围再返回目标已经没有意义了。

---

**涉及的知识点**  

| 知识点 | 简单解释（针对零基础的同学） |
|---|---|
| **广度优先搜索（BFS）** | 想象你在迷宫里一次只能走一步，先把所有可以一步到达的格子记下来（第一层），再从这些格子继续往外走一步（第二层），如此往复。层数越小表示走的步数越少，最先到达终点的层就是最短路径。 |
| **队列（Queue）** | 一种“先进先出”的数据结构，像排队买票一样：先加入的元素先被取出来。BFS 正是用队列来保证层序遍历的。 |
| **哈希集合（Set）** | 用来快速判断一个元素是否已经出现过，查找、插入的时间都很快（常数级），可以避免重复访问同一个状态导致死循环。 |

---

**逐步拆解**  

1. **初始化**  
   - 创建一个队列 `q`，把起始状态 `(position=0, speed=1, steps=0)` 放进去。  
   - 创建一个集合 `visited`，把 `(0,1)` 加进去，表示已经访问过。  

2. **进入循环**（只要队列不为空就一直循环）  
   a. 从队列头部弹出一个状态 `(pos, spd, step)`。  
   b. **检查是否到达目标**：如果 `pos == target`，直接返回 `step`（已经是最少指令数）。  
   c. **生成 “加速” 状态**：  
      - `next_pos = pos + spd`  
      - `next_spd = spd * 2`  
      - 如果 `next_pos` 在 `[-2*target, 2*target]` 且 `(next_pos, next_spd)` 未被访问，则加入队列，步数加 1。  
   d. **生成 “掉头” 状态**：  
      - `next_spd = -1 if spd > 0 else 1`（速度方向反转且大小变为 1）  
      - `next_pos = pos`（掉头时位置不变）  
      - 同样检查范围和是否已访问，满足条件就加入队列，步数加 1。  

3. **循环结束**（理论上不会出现，因为一定能到达目标），若循环意外结束返回 `-1` 表示出错。  

---

**代码**  

```python
from collections import deque

class Solution:
    def racecar(self, target: int) -> int:
        # 使用队列进行 BFS，队列中每个元素是 (当前位置, 当前速度, 已使用指令数)
        q = deque()
        q.append((0, 1, 0))               # 起始状态：位置 0，速度 +1，指令数 0
        visited = set()
        visited.add((0, 1))               # 记录已经访问过的状态，防止重复

        # 为了限制搜索范围，设定一个合理的边界
        # 超过 2*target 的位置再返回目标已经没有意义（因为最优解不会这么远）
        bound = target * 2

        while q:
            pos, spd, step = q.popleft()  # 取出队首元素

            # ① 检查是否已经到达目标位置
            if pos == target:
                return step               # 第一次碰到就是最少指令数

            # ② 产生 “加速” (A) 的新状态
            next_pos = pos + spd
            next_spd = spd * 2
            # 只在合理范围内且未访问过才加入队列
            if -bound <= next_pos <= bound and (next_pos, next_spd) not in visited:
                visited.add((next_pos, next_spd))
                q.append((next_pos, next_spd, step + 1))

            # ③ 产生 “掉头” (R) 的新状态
            # 掉头后速度变为相反方向且大小为 1
            rev_spd = -1 if spd > 0 else 1
            # 位置不变，只是改变速度
            if (pos, rev_spd) not in visited:
                visited.add((pos, rev_spd))
                q.append((pos, rev_spd, step + 1))

        # 按理说永远不会走到这里，因为一定能找到答案
        return -1
```

---

**举例走一遍**（`target = 3`）  

| 步骤 | 队列状态 (pos, spd, step) | 解释 |
|---|---|---|
| 初始 | `[(0, 1, 0)]` | 只剩起点 |
| 1. 取出 `(0,1,0)`，不是目标 | 生成 A → `(1,2,1)`；生成 R → `(0,-1,1)` | 加速到 1，或掉头保持在 0 速度 -1 |
| 2. 队列变为 `[(1,2,1), (0,-1,1)]` | 取出 `(1,2,1)`，不是目标 | 生成 A → `(3,4,2)`；生成 R → `(1,-1,2)` |
| 3. 队列变为 `[(0,-1,1), (3,4,2), (1,-1,2)]` | 取出 `(0,-1,1)`，不是目标 | 生成 A → `(-1,-2,2)`；生成 R → `(0,1,2)` |
| 4. 队列变为 `[(3,4,2), (1,-1,2), (-1,-2,2), (0,1,2)]` | 取出 `(3,4,2)`，**位置已等于目标** | 立即返回 `step = 2`，即最短指令数是 2（指令序列为 "AA"） |

整个搜索过程层层展开，第一次遇到位置 3 时正好在第 2 步，说明答案是 2。

---

**复杂度分析**  

- **时间复杂度**  
  BFS 会遍历所有满足 `|position| ≤ 2·target` 且速度在合理范围内的状态。每个状态只会进入队列一次。状态的总数大约是 `O(target·log target)`（因为速度每次翻倍，最多只会出现 `log(target)` 种不同的速度），所以时间复杂度可以认为是 `O(target·log target)`。在最坏情况下（比如 `target` 很大）会稍高，但对 `target ≤ 10⁴` 完全可接受。

- **空间复杂度**  
  需要存储队列和 `visited` 集合，最坏情况下也会保存 `O(target·log target)` 个状态，因此空间复杂度同样是 `O(target·log target)`。

## 解法二：最优解

**核心洞察**  
直接 BFS 暴力搜索虽然能得到答案，但会遍历大量无用状态。观察指令序列的结构会发现：

1. 连续的加速指令 `A…A` 会让位置按照等比数列增长：执行 `k` 次 `A` 后的位置是 `2^k - 1`，速度是 `2^k`。  
2. 为了尽快接近目标，最有可能的做法是先加速到某个 `2^k - 1`（**超过或恰好等于** target），然后**掉头**（`R`），再用剩余的指令把多余的距离消掉。  
3. 如果 `2^k - 1` 正好等于 target，答案就是 `k`（全部加速）。  
4. 否则有两种思路：
   - **超调后倒回**：先加速到 `2^k - 1`（k 次 `A`），再 `R`，然后把多余的 `2^k - 1 - target` 通过递归求解。总步数 = `k + 1 + dp[2^k - 1 - target]`。  
   - **少加一次再调头**：先加速 `k-1` 次得到位置 `2^{k-1} - 1`，`R`，再加速 `m` 次（`0 ≤ m < k-1`），再 `R`，此时已经向相反方向跑了一段距离。剩余的距离变成 `target - (2^{k-1} - 1) + (2^m - 1)`，递归求解。总步数 = `(k-1) + 1 + m + 1 + dp[ target - (2^{k-1} - 1) + (2^m - 1) ]`。  
5. 取上述两种方案的最小值即为 `dp[target]`。  
6. 由于 `target ≤ 10⁴`，递归深度和状态数都很小，使用 **记忆化搜索（DP + 递归 + 哈希表）** 可以在毫秒级得到答案。

这就是“从暴力搜索到状态压缩的转变”：我们不再遍历所有可能的指令序列，而是只在每个 `target` 上考虑 **两种有意义的分支**，大幅削减搜索空间。

---

**涉及的知识点**  

| 知识点 | 简单解释 |
|---|---|
| **动态规划（DP）** | 把一个大问题拆成若干子问题，先解决子问题再合并答案。这里我们用 `dp[t]` 表示到达位置 `t` 的最少指令数。 |
| **递归 + 记忆化（Memoization）** | 用函数自己调用自己来解决子问题，为了避免重复计算，把已经算好的 `dp[t]` 存进字典，下次直接返回。 |
| **位运算 / 幂次计算** | 计算 `2^k` 常用左移或 `1 << k`，因为 `2` 的幂在本题出现频繁。 |
| **贪心思考** | 通过观察发现“最优解一定是先连续加速若干次”，这是一种对问题结构的直觉（贪心）帮助我们剪枝。 |

---

**逐步拆解**  

1. **准备工作**  
   - 定义一个函数 `dp(t)`，返回到达位置 `t` 的最少指令数。使用 `@lru_cache(None)`（或手写字典）来记忆化。  

2. **基准情况**  
   - 当 `t == 0` 时不需要任何指令，返回 `0`。  
   - 当 `t == 1` 时只需要一次 `A`，返回 `1`（可直接算出来或交给递归处理）。  

3. **找到最小的 `k` 使得 `2^k - 1 >= t`**  
   - 从 `k = 0` 开始累加 `2^k - 1`，或者用位运算快速求。  
   - 记 `reach = (1 << k) - 1` 为第 `k` 次连续加速后能到达的最远位置。  

4. **检查是否恰好等于目标**  
   - 如果 `reach == t`，说明只需要 `k` 次加速，直接返回 `k`。  

5. **方案一：超调后倒回**  
   - 超过目标后执行一次掉头，再把多余的距离 `reach - t` 递归求解。  
   - 步数 = `k`（加速） + `1`（掉头） + `dp[reach - t]`。  

6. **方案二：少加一次再调头**  
   - 只加 `k-1` 次，得到位置 `pre = (1 << (k-1)) - 1`，此时速度是 `2^{k-1}`。  
   - 执行一次掉头（`R`），速度变为 `-1`。  
   - 接着可以再做 `m` 次加速（`0 ≤ m < k-1`），这会在负方向上走 `2^m - 1` 的距离。  
   - 再次掉头（`R`）恢复正方向，之后仍然需要把剩余的距离走到 `t`。  
   - 剩余的目标距离变为 `t - pre + (2^m - 1)`（因为我们在负方向上走了 `2^m - 1`，相当于把目标往回拉）。  
   - 递归求 `dp[t - pre + (1 << m) - 1]`。  
   - 总步数 = `(k-1)`（前面的加速） + `1`（第一次掉头） + `m`（第二段加速） + `1`（第二次掉头） + `dp[ t - pre + (1 << m) - 1 ]`。  
   - 对所有合法的 `m` 取最小值。  

7. **取最小**  
   - `ans = min( 方案一, 所有方案二 )`。  
   - 将 `ans` 存入记忆化表并返回。  

8. **主函数**  
   - 只需要调用 `dp(target)` 即可得到答案。  

---

**代码**  

```python
from functools import lru_cache

class Solution:
    def racecar(self, target: int) -> int:
        # 记忆化搜索：保存已经算好的 dp[t]，避免重复递归
        @lru_cache(None)
        def dp(t: int) -> int:
            # 基础情况：已经在原点，不需要任何指令
            if t == 0:
                return 0

            # 找到最小的 k 使得 2^k - 1 >= t
            k = 0
            # (1 << k) 表示 2 的 k 次方
            while (1 << k) - 1 < t:
                k += 1

            # 完全匹配的情况：恰好用 k 次 A 就能到达
            if (1 << k) - 1 == t:
                return k

            # ------------------- 方案一：超调后倒回 -------------------
            # 先加速 k 次到 reach，然后 R 再回到 target
            reach = (1 << k) - 1               # 2^k - 1
            # 多走的距离是 reach - t，需要递归求解
            ans = k + 1 + dp(reach - t)        # k 次 A + 1 次 R + 递归

            # ------------------- 方案二：少加一次再调头 -------------------
            # 只加 k-1 次 A，得到 pre = 2^{k-1} - 1
            pre = (1 << (k - 1)) - 1           # 2^{k-1} - 1
            # 这里我们在 pre 的位置掉头，速度变为 -1
            # 然后可以再做 m 次加速（0 <= m < k-1）
            # 这会在负方向上走 (2^m - 1) 的距离
            # 再掉头回来，剩余的目标距离是 t - pre + (2^m - 1)
            for m in range(k - 1):
                # 先加 k-1 次 A，再 R，再加 m 次 A，再 R
                # 步数 = (k-1) + 1 + m + 1
                # 剩余距离递归求解
                cur = (k - 1) + 1 + m + 1 + dp(t - pre + (1 << m) - 1)
                ans = min(ans, cur)            # 取最小

            return ans

        # 调用记忆化函数得到最终答案
        return dp(target)
```

---

**举例走一遍**（`target = 6`）  

1. **第一次调用 `dp(6)`**  
   - 找到最小 `k` 使 `2^k - 1 >= 6` → `k = 3`（因为 `2^3-1 = 7`）  
   - `reach = 7`，不等于目标，进入两种方案。  

2. **方案一（超调）**  
   - 步数 = `k + 1 + dp(7 - 6)` = `3 + 1 + dp(1)`  
   - 需要先求 `dp(1)`：  
     - `k = 1`，`2^1-1 = 1` 正好等于目标 → `dp(1) = 1`（只需要一次 A）  
   - 方案一总步数 = `3 + 1 + 1 = 5`  

3. **方案二（少加一次）**  
   - `pre = 2^{k-1} - 1 = 2^{2} - 1 = 3`  
   - 对 `m` 进行遍历：`m = 0`、`m = 1`（因为 `k-1 = 2`）  

   - **`m = 0`**  
     - 计算 `cur = (k-1) + 1 + m + 1 + dp( t - pre + (2^m - 1) )`  
     - `cur = 2 + 1 + 0 + 1 + dp(6 - 3 + 0) = 4 + dp(3)`  
     - 需要 `dp(3)`：  
       - `k = 2`，`2^2-1 = 3` 正好等于目标 → `dp(3) = 2`（指令 "AA"）  
     - `cur = 4 + 2 = 6`  

   - **`m = 1`**  
     - `cur = 2 + 1 + 1 + 1 + dp(6 - 3 + (2^1 - 1))`  
     - `cur = 5 + dp(6 - 3 + 1) = 5 + dp(4)`  
     - 需要 `dp(4)`：  
       - `k = 3`（`2^3-1 = 7`）  
       - 方案一： `3 + 1 + dp(7-4=3) = 4 + dp(3) = 4 + 2 = 6`  
       - 方案二： `pre = 2^{2} - 1 = 3`，遍历 `m' = 0,1`  
         - `m'=0` → `cur' = 2+1+0+1+dp(4-3+0)=4+dp(1)=4+1=5`  
         - `m'=1` → `cur' = 2+1+1+1+dp(4-3+1)=5+dp(2)`  
           - `dp(2)` 计算得到 `4`（序列 "ARA"） → `cur'=9`  
         - 取最小 `5`  
       - 所以 `dp(4) = min(6,5) = 5`  
     - `cur = 5 + 5 = 10`  

   - 方案二取最小值 `min(6,10) = 6`  

4. **比较两种方案**  
   - 方案一得到 `5`，方案二得到 `6`，取最小 → `dp(6) = 5`  

因此返回 `5`，对应的最优指令序列是 `"AAARA"`（两次加速到 3，第三次加速到 7，掉头回到 6）。  

整个递归过程中每个子目标只被计算一次（记忆化），所以实际执行的状态数量非常有限。

---

**复杂度分析**  

- **时间复杂度**  
  对每个 `t`（`1 ≤ t ≤ target`）我们只会尝试两类分支：  
  1. 超调一次（常数时间）  
  2. 在 `k-1` 次加速后遍历 `m = 0 … k-2`（最多 `log₂ t` 次）  
  因此每个 `t` 的计算时间是 `O(log t)`，累计到 `target` 的总时间是  

  \[
  O\!\left(\sum_{t=1}^{target} \log t\right)=O(target \log target)
  \]

  对于 `target ≤ 10⁴`，这非常快（毫秒级）。

- **空间复杂度**  
  记忆化表保存了 `dp[t]`（`t = 0 … target`）共 `target+1` 个整数，递归调用的最大深度不超过 `log₂ target`。  
  所以空间复杂度是 `O(target)`。

## 对比总结

| 维度 | 解法一：暴力 BFS | 解法二：动态规划（记忆化递归） |
|---|---|---|
| **核心思路** | 逐层枚举所有指令序列，使用队列层层展开，第一次到达目标即为最短 | 利用加速后位置的幂次特性，只在每个 `target` 上考虑两种“有意义”的分支，递归求解子问题 |
| **关键洞察** | “最短路径 = BFS 第一次碰到目标” | “连续加速后位置 = 2^k‑1”，最优解一定是先加速到最近的 2^k‑1 再调头（或少加一次再调头） |
| **时间复杂度** | 大约 `O(target·log target)`，但实际遍历的状态更多，最坏情况下会更接近指数级 | `O(target·log target)`，遍历的状态严格受 `log target` 限制，实际更快 |
| **空间复杂度** | `O(target·log target)`（队列+集合） | `O(target)`（记忆化表） |
| **实现难度** | 思路直观，代码相对简单，适合第一次接触 BFS 的同学 | 需要理解幂次结构、递归与记忆化，思路稍微抽象，但代码行数更少 |
| **学习收获** | 掌握 BFS、队列、去重集合的使用，体会“层序遍历”求最短路径的通用技巧 | 学会用 **动态规划** 把大问题拆解为子问题，体会“状态压缩”和“贪心+DP”相结合的思考方式 |

**最重要的收获**  
- **从暴力到结构化**：先用 BFS 直接实现，帮助你感受“最短路径 = BFS 第一次到达”。随后通过观察指令序列的数学规律（`2^k - 1`），我们把搜索空间压缩到极少的关键状态，得到了更高效的 DP 解法。  
- **算法思维的迁移**：这道题展示了如何把“遍历所有可能”转化为“只遍历有意义的可能”，这是一种在很多硬题中都会用到的思考模式。掌握了这种迁移，你以后面对更复杂的题目也能快速找到突破口。

## 解法一：暴力 / 最直觉解  

**思路**  
> 用大白话解释：面对这道题，一个没学过算法的人第一反应会怎么做？  
>  
> 我们先把「路径」的定义写清楚：从树中的任意一个节点出发，沿着父子关系向左或向右走，走到的每个节点只能走一次，走到哪儿就把那个节点的值加进总和。  
>  
> 没有任何技巧的情况下，最直接的想法就是**枚举**所有可能的路径，然后把每条路径的节点值相加，记录最大的那个和。  
>  
> 因为「路径」可以从任意节点开始、也可以在任意节点结束（不一定要经过根），所以我们需要遍历**每一个节点**作为「路径的起点」，并且从该起点继续向下探索所有可能的走法（左、右、左再右、右再左…），把每一种走法算出总和，最后取最大值。  

**涉及的知识点**  

| 知识点 | 解释（面向零基础） |
|--------|-------------------|
| 二叉树遍历（深度优先） | 从根节点出发，一直往下走到叶子节点的过程。常见的有前序·中序·后序，这里我们用「递归」的方式模拟「先走左子树，再走右子树」的深度优先搜索（DFS）。 |
| 递归 | 函数自己调用自己。把「把树的每条路径都算一遍」的任务拆成「算左子树的所有路径」+「算右子树的所有路径」+「把左、右合起来」的子任务。 |
| 全局变量（或外部可变对象） | 用来在递归的每一次调用结束后，把当前找到的最大路径和保存下来，供后面的调用继续比较。 |

**逐步拆解**  

1. **准备一个全局变量 `ans`**，初始值设为负无穷（因为节点值可能全是负数）。  
2. **定义递归函数 `dfs(node)`**：  
   - 如果 `node` 为 `None`（空），直接返回 0（空节点不贡献路径）。  
   - 递归求左子树的最大“单向贡献” `left = dfs(node.left)`。如果左子树的贡献为负数，我们直接把它当作 0（不取左子树）。  
   - 同理求右子树的最大“单向贡献” `right = dfs(node.right)`。  
   - **计算「经过当前节点的路径和」**：`node.val + left + right`。这条路径会把左、右子树都接上，形成「左—根—右」的完整路径。把它和 `ans` 做比较，更新 `ans`。  
   - **返回给父节点的「单向最大贡献」**：`node.val + max(left, right)`。因为向上走的路径只能选左或右其中一条，不能同时走两边。返回值用于父节点继续计算。  
3. **从根节点调用 `dfs(root)`**，递归会遍历整棵树并更新 `ans`。  
4. **返回 `ans`**，即为答案。  

**代码**  

```python
# -*- coding: utf-8 -*-
# 下面的代码实现了「暴力」思路：遍历每个节点并递归计算所有可能的路径和
# 为了让完全没有算法经验的同学也能看懂，代码每一行都写了中文注释

class Solution:
    def maxPathSum(self, root):
        """
        :type root: TreeNode
        :rtype: int
        """
        # ans 用来保存全局的最大路径和，初始设为非常小的数
        self.ans = float('-inf')

        # dfs 是深度优先搜索的递归函数，返回「从当前节点向下走，最多只能选一条支路」的最大贡献值
        def dfs(node):
            # 如果当前节点为空，直接返回 0（不贡献路径）
            if not node:
                return 0

            # 递归求左子树的最大单向贡献
            left = dfs(node.left)
            # 如果左子树的贡献为负数，说明带上左子树只会让和更小，直接把它当作 0
            left = max(left, 0)

            # 递归求右子树的最大单向贡献，同理处理负数
            right = dfs(node.right)
            right = max(right, 0)

            # 计算「经过当前节点」的路径和：左子树贡献 + 当前节点值 + 右子树贡献
            # 这条路径可以把左、右都接上，形成一个完整的「左-根-右」路径
            cur_path_sum = node.val + left + right

            # 用全局变量 ans 记录目前为止出现的最大路径和
            self.ans = max(self.ans, cur_path_sum)

            # 返回给父节点的「单向最大贡献」：只能选左或右其中一条继续向上
            # 因为向上只能走一条路，所以只取 left、right 中的较大者
            return node.val + max(left, right)

        # 从根节点开始递归遍历整棵树
        dfs(root)

        # 最后 ans 中保存的就是任意非空路径的最大和
        return self.ans
```

**举例走一遍**（示例 1：`root = [1,2,3]`）  

树结构  

```
      1
     / \
    2   3
```

| 步骤 | 递归调用 | left (左子树返回) | right (右子树返回) | cur_path_sum (左+根+右) | 更新的 ans | 返回给父节点的值 |
|------|----------|-------------------|--------------------|------------------------|------------|-------------------|
| 1 | `dfs(2)` | `dfs(None)=0` → left=0 | `dfs(None)=0` → right=0 | `2+0+0 = 2` | `ans = max(-inf,2)=2` | `2 + max(0,0) = 2` |
| 2 | `dfs(3)` | 同上 → left=0 | 同上 → right=0 | `3+0+0 = 3` | `ans = max(2,3)=3` | `3 + max(0,0) = 3` |
| 3 | `dfs(1)` | left = **2** (来自步骤 1) → left = max(2,0)=2 | right = **3** (来自步骤 2) → right = max(3,0)=3 | `1+2+3 = 6` | `ans = max(3,6)=6` | `1 + max(2,3) = 4`（返回给根的父节点，根本没有父节点，这个返回值不再使用） |

最终 `ans = 6`，即路径 `2 -> 1 -> 3` 的和。  

**复杂度分析**  

- **时间复杂度**：`O(N)`，其中 `N` 为树中节点数。每个节点只会被 `dfs` 访问一次，虽然在「暴力」的描述里提到了「枚举所有路径」，但实际实现中我们利用了递归的剪枝（把负贡献当作 0），所以整体仍是线性遍历。  
- **空间复杂度**：`O(H)`，递归栈的深度等于树的高度 `H`（最坏情况下 `H = N`，即链状树），除此之外只用了常数级别的额外变量。

## 解法二：最优解（后序遍历 + 动态规划）  

**核心洞察**  
> 解法一已经是 `O(N)` 的遍历了，为什么说它「慢」？  
>  
> 实际上，解法一的代码已经是最常见、最优的实现方式。这里我们把它重新组织成**「后序遍历 + 动态规划」**的思路，帮助初学者从「把所有路径都算一遍」的直觉，转向「每个子树只需要保存两个信息」的抽象。  
>  
> 关键的「灵光一现」是：**对每个节点来说，只有两件事需要记住**  
> 1. **向上贡献的最大单边和**（只能选左或右，供父节点继续使用）。  
> 2. **经过该节点的最大路径和**（左 + 根 + 右），用于更新全局答案。  
>  
> 当我们从叶子向根部「后序」回溯时，这两个值就可以在 **O(1)** 时间内合并得到父节点的值，整个过程只遍历一次树，空间只用递归栈。  

**涉及的知识点**  

| 知识点 | 解释（通俗） |
|--------|--------------|
| 后序遍历（Depth‑First Search, DFS） | 先递归访问左子树 → 再访问右子树 → 最后处理当前节点。想象成「先把所有子问题搞定，再来解决本题」。 |
| 动态规划（DP）在树上的应用 | 对每个子树算出「最优子结构」并保存，父节点利用这些已知最优子结构快速得到自己的最优解。这里的「子结构」就是左、右子树的两种信息。 |
| 全局变量（或外部可变对象） | 用来在递归的每一步都更新「全局最大路径和」。因为答案可能出现在任意子树内部，而不一定是根节点所在的路径。 |

**逐步拆解**  

1. **初始化全局最大答案 `max_sum = -inf`**。  
2. **定义递归函数 `postorder(node)`**（后序遍历）：  
   - 若 `node` 为 `None`，返回 0（空树不贡献）。  
   - 递归得到左子树的「单边最大贡献」`left = max(postorder(node.left), 0)`；负数直接当 0。  
   - 同理得到右子树的「单边最大贡献」`right = max(postorder(node.right), 0)`。  
   - **计算「穿过当前节点的路径和」**：`price_newpath = node.val + left + right`。这条路径把左、右子树都接上，是可能的「全局答案」候选。  
   - 用 `max_sum = max(max_sum, price_newpath)` 更新全局答案。  
   - **返回「向上贡献的最大单边和」**：`node.val + max(left, right)`。因为向上只能选左或右其中一条。  
3. **从根节点调用 `postorder(root)`**，递归遍历整棵树并更新 `max_sum`。  
4. **返回 `max_sum`**。  

**代码**  

```python
# -*- coding: utf-8 -*-
# 最优解：后序遍历 + 动态规划（每个节点只保存两条信息）
# 代码同样逐行加注释，帮助零基础的同学快速读懂

class Solution:
    def maxPathSum(self, root):
        """
        :type root: TreeNode
        :rtype: int
        """
        # 全局变量，用来保存遍历过程中出现的最大路径和
        self.max_sum = float('-inf')

        # 后序遍历的递归函数
        def postorder(node):
            # 空节点直接返回 0，表示它不贡献任何正数
            if not node:
                return 0

            # 递归求左子树的「单边最大贡献」，如果是负数就当作 0（不取）
            left = max(postorder(node.left), 0)

            # 递归求右子树的「单边最大贡献」，同理处理负数
            right = max(postorder(node.right), 0)

            # 以当前节点为最高点的路径和 = 左贡献 + 节点值 + 右贡献
            price_newpath = node.val + left + right

            # 更新全局最大路径和
            self.max_sum = max(self.max_sum, price_newpath)

            # 返回给父节点的「单边最大贡献」：只能选左或右中较大的那条继续向上
            return node.val + max(left, right)

        # 从根节点开始后序遍历
        postorder(root)

        # 最终的答案保存在 self.max_sum 中
        return self.max_sum
```

**举例走一遍**（仍以示例 1 `root = [1,2,3]` 为例）  

递归的调用顺序是后序：`dfs(2) → dfs(3) → dfs(1)`。我们记录每一步的 `left`, `right`, `price_newpath`, `self.max_sum` 以及函数返回值。

| 调用顺序 | 节点值 | left (左子返回) | right (右子返回) | price_newpath = val+left+right | 更新后的 `self.max_sum` | 返回给父节点的值 |
|----------|--------|-----------------|------------------|-------------------------------|------------------------|-------------------|
| `postorder(2)` | 2 | 0 (左子为 None) | 0 (右子为 None) | 2 + 0 + 0 = **2** | `max(-inf,2)=2` | `2 + max(0,0) = 2` |
| `postorder(3)` | 3 | 0 | 0 | 3 + 0 + 0 = **3** | `max(2,3)=3` | `3 + max(0,0) = 3` |
| `postorder(1)` | 1 | 2 (左子返回) | 3 (右子返回) | 1 + 2 + 3 = **6** | `max(3,6)=6` | `1 + max(2,3) = 4`（返回给根的父节点，根没有父节点） |

遍历结束后 `self.max_sum = 6`，即答案。  

**复杂度分析**  

- **时间复杂度**：`O(N)`，每个节点只被访问一次，所有计算都是常数时间。相较于「暴力」的描述，它没有额外的「枚举」步骤，是真正的最优线性解。  
- **空间复杂度**：`O(H)`，递归栈的深度等于树的高度 `H`（最坏 `O(N)`，平均 `O(log N)`），没有使用额外的数组或哈希表。

## 对比总结  

| 维度 | 解法一：暴力直觉 | 解法二：后序遍历 + 动态规划 |
|------|----------------|---------------------------|
| **核心思路** | 对每个节点递归计算「左、右单向贡献」并在递归过程中直接更新全局最大值。 | 把「单向贡献」和「穿过当前节点的完整路径」抽象为两个状态，在后序遍历中自底向上合并。 |
| **时间复杂度** | `O(N)`（每个节点一次） | `O(N)`（每个节点一次） |
| **空间复杂度** | `O(H)`（递归栈） | `O(H)`（递归栈） |
| **代码可读性** | 直观但每一步都在「返回」时顺带更新，可能让人难以把「两个状态」区分开。 | 明确分离「返回值」与「全局答案」两部分，思路更清晰，易于迁移到类似的「树上 DP」问题。 |
| **学习收获** | 认识到递归可以遍历全部路径，体会「把负贡献当 0」的剪枝技巧。 | 掌握**后序遍历 + DP**的通用套路：**子问题的最优解 → 合并 → 更新全局最优**，这是解决多数树形 DP 题目的根本方法。 |

**最重要的收获**：  
- **树上动态规划的思想**——每个子树只需要保留「向上贡献」和「局部最佳」两种信息，整个问题的最优解可以在一次遍历中完成。  
- 以后遇到类似「某种结构的最大/最小」问题时，先思考「能否把子结构的最优信息压缩成常数个值”，再用后序遍历自底向上合并，这往往就是最优解的钥匙。

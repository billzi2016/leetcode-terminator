## 解法一：暴力 / 最直觉解  

**思路**  
把这道题想成“在一堆数字里找出两个人，让他们的年龄加起来正好等于某个目标”。如果你没有学过任何算法，最自然的办法就是：  
1）先把第一个人挑出来；  
2）再把后面每一个人都尝试一次，看看他们的年龄加起来是否等于目标；  
3）如果不行，就换成第二个人，再和后面的人全部配对；  
4）一直这么做，直到找到一对满足条件的组合为止。  
这就是最直接的、全遍历的思路——把所有可能的两两组合都检查一遍。

**涉及的知识点**  
- **数组遍历**：顺序访问数组中的每个元素，类似把一排水果一个一个拿出来看。  
- **嵌套循环**：在遍历的过程中再嵌套一次遍历，形成“里外两层循环”，用来生成所有的元素对。  
- **索引**：数组里每个位置都有一个编号（下标），我们需要把这些编号记录下来，因为题目要求返回的是位置而不是数值本身。

**逐步拆解**  
1. **准备**：拿到数组 `nums` 和目标值 `target`。  
2. **外层循环 i**：从第 0 位开始，一直遍历到倒数第二位（因为最后一位已经没有后面的元素可以配对了）。  
3. **内层循环 j**：对于每个外层的 `i`，从 `i+1` 开始遍历到数组末尾，尝试所有后面的元素。  
4. **检查**：计算 `nums[i] + nums[j]` 是否等于 `target`。  
5. **返回**：如果相等，直接返回 `[i, j]`（这就是答案）。  
6. **结束**：如果所有循环结束仍未找到，按照题目假设不会出现这种情况（因为必有唯一解），这里可以返回空列表或抛异常。

**代码**  

```python
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        # 外层遍历每一个元素，i 是第一个数的下标
        for i in range(len(nums)):
            # 内层遍历 i 之后的所有元素，j 是第二个数的下标
            for j in range(i + 1, len(nums)):
                # 计算这两个数的和
                current_sum = nums[i] + nums[j]
                # 如果恰好等于目标值，就找到了答案
                if current_sum == target:
                    # 按题目要求返回下标列表
                    return [i, j]
        # 按题目假设这里不会执行到，因为一定有唯一解
        return []
```

**举例走一遍**（示例 1：`nums = [2,7,11,15]`, `target = 9`）  

| 步骤 | i | j | nums[i] | nums[j] | current_sum | 判断 | 结果 |
|------|---|---|--------|--------|-------------|------|------|
| 1 | 0 | 1 | 2 | 7 | 2+7=9 | 9 == 9 → 成立 | 返回 `[0,1]`，函数结束 |
| （后面的循环不会再执行） |   |   |   |   |   |   |   |

执行过程细化：  
- 第一次进入外层 `i=0`（`nums[0]=2`）。  
- 内层从 `j=1` 开始，取 `nums[1]=7`，计算 `2+7=9`，恰好等于目标。  
- 立即返回 `[0,1]`，不再继续遍历。

**复杂度分析**  
- **时间复杂度**：外层循环 `n` 次，内层最坏情况下也要遍历 `n-1` 次，形成约 `n*(n-1)/2` 次比较，量级是 **O(n²)**。  
- **空间复杂度**：只使用了常数级的额外变量（`i、j、current_sum`），不随输入规模增长，故为 **O(1)**。

## 解法二：最优解  

**核心洞察**  
暴力解法慢的根源在于**每次都要遍历后面的所有元素**来找“配对”。如果我们能在 **一次遍历** 的过程中，**快速判断**“我之前见过的数里有没有恰好可以配成目标的数”，就不需要再二次循环。  
观察到：我们只需要**知道每个已经遍历过的数的值对应的下标**，而查找一个数是否出现过，**哈希表（字典）**可以在 **常数时间 O(1)** 完成。这就是从暴力到线性时间的“灵光一现”。

**涉及的知识点**  
- **哈希表（字典）**：一种把“键”映射到“值”的数据结构，内部通过哈希函数把键散列到数组的某个位置，理论上查找、插入、删除的时间都是 **O(1)**。可以把它想象成“带有快速检索功能的记事本”，我们把已经看到的数字记下来，想要找某个数字时只要翻一页就能找到。  
- **一次遍历**：只走一遍数组，在遍历的同时完成“记录”和“查询”两件事，避免了二次循环。

**逐步拆解**  
1. **准备**：创建一个空的哈希表 `num_to_index`，用于存放「数字 → 其下标」的映射。  
2. **遍历数组**：用单个 `for i, num in enumerate(nums)` 循环，`i` 是当前下标，`num` 是当前数值。  
3. **计算 complement**：`complement = target - num`，这就是我们需要的另一半数。  
4. **查询哈希表**：检查 `complement` 是否已经在 `num_to_index` 中出现过。  
   - 若出现，说明之前的某个数正好可以和当前 `num` 配对，直接返回 `[num_to_index[complement], i]`。  
   - 若未出现，继续第 5 步。  
5. **记录当前数**：把 `num` 和它的下标 `i` 放进哈希表 `num_to_index[num] = i`，供后面的元素使用。  
6. **结束**：遍历结束后一定已经返回答案（题目保证唯一解），否则返回空列表。

**代码**  

```python
from typing import List

class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        # 哈希表：键是已经遍历过的数字，值是它们对应的下标
        num_to_index = {}
        # 只遍历一次数组
        for i, num in enumerate(nums):
            # 需要的另一半数
            complement = target - num
            # 看看这另一半数之前是否出现过
            if complement in num_to_index:
                # 如果出现过，直接返回配对的下标
                return [num_to_index[complement], i]
            # 否则把当前数字和下标记下来，供后面的元素查找
            num_to_index[num] = i
        # 按题目假设这里不会被执行，因为一定有唯一解
        return []
```

**举例走一遍**（示例 1：`nums = [2,7,11,15]`, `target = 9`）  

| 步骤 | i | num | complement = target - num | 哈希表状态 (num→index) | complement 是否在表中 | 返回值 |
|------|---|-----|---------------------------|------------------------|------------------------|--------|
| 1 | 0 | 2 | 9-2 = 7 | `{}` | 7 不在 | 记录 `2:0` → `{2:0}` |
| 2 | 1 | 7 | 9-7 = 2 | `{2:0}` | 2 在表中 → 找到配对 | 返回 `[0,1]`，函数结束 |

执行细化：  
- 第一次循环，`num=2`，`complement=7` 未出现，记录 `{2:0}`。  
- 第二次循环，`num=7`，`complement=2` 已经在哈希表里，得到配对下标 `[0,1]`，立即返回。

**复杂度分析**  
- **时间复杂度**：只遍历一次数组，且每次查找/插入哈希表的时间均为 **O(1)**，整体为 **O(n)**。  
- **空间复杂度**：哈希表最多会存储 `n` 条键值对（每个元素对应一个下标），因此为 **O(n)** 的额外空间。

## 对比总结  

| 维度 | 解法一：暴力 | 解法二：哈希表（最优） |
|------|--------------|------------------------|
| **核心思路** | 完全枚举所有两两组合 | 边遍历边记录，利用哈希表实现常数时间查找 |
| **时间复杂度** | O(n²)（随 n 的平方增长） | O(n)（线性增长） |
| **空间复杂度** | O(1)（只用常数级变量） | O(n)（需要哈希表存储已遍历元素） |
| **适用场景** | 数据规模极小或仅作演示时 | 数据规模中等以上，要求效率时 |
| **学习收获** | 理解最直接的“穷举”思路，掌握循环嵌套的写法 | 学会使用哈希表把“查找”从线性提升到常数，体会空间换时间的经典技巧 |

> **最重要的收获**：在面对“在集合中找配对”这类问题时，**先思考有没有可以用 O(1) 查找的数据结构**（如哈希表），往往能把暴力的 O(n²) 直接降到 O(n)。这也是许多面试题的核心思路——**用合适的辅助结构来避免重复工作**。
